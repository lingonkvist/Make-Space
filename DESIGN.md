# Make Space: design notes

Why things are the way they are. What the code does is in the code and the tests; the README is for players. This file only holds what neither can: the rules we hold ourselves to, and the ideas we turned down with the reason.

Keep it short. An entry needs a reason, or it does not belong. When a test enforces something, link the test instead of describing the behavior.

## Principles

- **Silence has meaning.** No dot means no signal. A rule that can only sort-of fire stays quiet.
- **A wrong green is a critical bug.** Green is high confidence; yellow is a soft hint and a wrong one is a tuning issue.
- **Make Space never deletes on its own.** Every delete is the player's click.
- **WoW Forever only** (Interface 16001). Classic Era was dropped in 0.5.0.
- **Prefer modern namespaced APIs** (`C_Container`, `C_Item`) over the old globals.

## Where things live

| Module | Job |
|---|---|
| `verdict.lua` | Pure. `(item, state)` to a verdict from an ordered rule list (`RULES`). No game calls. |
| `notes.lua` | The words of every yellow and green: reason, title, detail. |
| `safety.lua` | Protections that veto a green (reagents, open quests, tools, Hearthstone). |
| `auction.lua`, `curves.lua`, `live.lua`, `market.lua` | Auction snapshot, price curves, Auctionator live prices, region and faction. |
| `progress.lua` | Whether a profession is being leveled (idle or settling). |
| `bank.lua` | What a verdict means once the item is banked. |
| `makeroom.lua` | Pure plan for full bags and the loot window. |
| `scanner.lua` | The only module that reads the game for item data. Gathers, judges, caches. |
| `overlay.lua`, `tooltip.lua`, `menu.lua`, `lootbutton.lua` | Paint dots, hover text, the mark menu, the delete button. |
| `overrides.lua`, `commands.lua`, `dump.lua` | Player marks, slash commands, inventory dump. |
| `MakeSpace.lua` | Events and wiring. |
| `data/` | Generated by `tools/`; never edited by hand. |

## Invariants and the tests that hold them

- **Reagents, open quest items, tools and the Hearthstone are never green, and make-room never offers a protected item:** `tests/invariants_spec.lua`.
- **Real inventories get no green they should not, and recipe reagents are never green at any level, class or faction:** `tests/replay_spec.lua`.
- **Every yellow has a reason, a 2 to 4 word title with no digits, and a single detail; reasons never hint at the auction house:** `tests/verdict_spec.lua`, "Yellow headings".
- **Old or missing auction data only ever blocks a green, never grants one:** `tests/verdict_spec.lua`, "Old Auctionator readings only ever block".
- **A delete runs only if the slot still holds the planned item and stack:** `tests/lootbutton_spec.lua`.
- **Verdict, makeroom, bank and safety stay pure** (no game calls). By convention: the tests load them without a client, and `tools/check_globals.js` catches stray globals.
- **The scanner's cache key must include every input a verdict uses.** No test catches a missing one. When a rule reads a new item field, add it to the key in `scanner.lua`.

## Adding a rule

1. Write the failing test in `tests/verdict_spec.lua`.
2. Add the rule to `RULES` in `verdict.lua`, with its wording in `notes.lua`.
3. New item field: gather it in `scanner.lua` and add it to the cache key.
4. New event that changes verdicts: handle it in `MakeSpace.lua`.
5. Run `python3 -I tests/run_tests.py`, then say what to look at in game.

## Decisions

- **Grays: one dot, on the cheapest.** A full bag would otherwise be a wall of green. At a vendor every gray that sells lights, since selling them all is the point of the visit (0.7.5).
- **One delete per click.** The game refuses a second delete in the same click ("Interface action failed because of an AddOn"), and a timer has no click behind it, so it cannot wait its way around that. The button deletes the first planned item and the next click takes the next (0.7.4).
- **A quest you have not taken does not hold back a consumable hint.** The tooltip names the quest under the hint instead, so the player decides (0.7.5).
- **A quest row on an item with recipe uses skips quests 10+ levels from acceptable.** Those items are cheap to buy again by the time the quest opens, and the row would only keep them in the bag. A quest in your log always shows (0.7.5).
- **Class-cannot-use rules are white only.** Greens and better can sell well, and the auction check holds a pricey one back.
- **In the bank, a verdict stays only if it holds for any character.** People bank things on purpose, often for an alt (`bank.lua`).
- **Quiver, ammo and profession bags are not room for loot,** and deleting from them frees nothing.
- **`LOOT_OPENED`'s first argument is the auto-loot flag,** not a cleared slot.
- **The loot window rescans once now and at most once on the next frame,** however many loot events a fast-loot addon fires.

- **Tooltips stay at three lines or fewer, two when possible.** Title (the opinion), detail (the fact behind it), then at most one price or source line. A quest in your log comes first, then the price, then any other quest row; the rest drop. A quest in your log may make a fourth line under a two-line detail (0.7.5).
- **Titles state a fact, not an instruction.** "Needed later", not "Bank it". An action stays only where the item has one obvious thing to do (Open it, Library book, Trade for a buff, Consider auctioning). `notes.lua` has the standard (0.7.5).
- **Cheap to rebuy is green, on evidence.** A stack is cheap when its price is known (listed in the price data or live), it sells to a vendor, it can be traded, and its value is under half the gray bar for your level. Unlisted items may be rare, so they never count. A cheap stack that a quest wants or that can be opened is silent, never green (0.7.5).
- **The auction check stands aside for an item no vendor buys that the auction pays next to nothing for.** Under the same line as "cheap to rebuy", a completed quest item that lists for a silver is green, not held back. With a vendor price the check stays, since selling beats deleting (0.7.5).
- **Gear names the required level when it has one.** The item level joins it only when it is the higher number, and "you are N" goes only with a required level, since an item level is not a character level. Level 1 counts as no requirement (0.7.5).
- **Every tooltip line fits 45 characters, and says one fact.** Notes are written to fit, not wrapped: names are cut with `Notes.Cut`, lists name two and count the rest, and a completed quest is one line (`[40] Name (completed)`). `tests/notes_spec.lua` feeds each note its longest realistic input. A fixed shape beats merging lines per tooltip, because the same verdict should always look the same (0.7.5).
- **One word per idea.** "Requires" for requirements, as the item's own tooltip says it, "Used by", "Best for you:", "Hand in to". A detail never repeats a word its title already says: "Needed later" is followed by "Requires", not "Needs" (0.7.5).
- **"Needed later" never shows while a quest in your log wants the item.** The quest row says why instead (0.7.5).
- **A known recipe is read from the tooltip's "Already known" line.** Soulbound, it is green (nothing can use or sell it); tradeable, it is a yellow hint that it may sell, with the usual price line. Learning a recipe clears the stored answers for recipes, since it changes the tooltip of every copy still in the bags (0.7.6).
- **A trinket is never called outleveled.** One is worn for what it does. A trinket the scanner read as plain is a missed Use line, not a dull trinket, and a wrong green is the costly mistake (0.7.6).
- **Read-only items are a hand-kept list** (`data/read_only_items.lua`): lore books and manuals whose text is on any wiki. An entry needs no use effect, no quest it starts, no vendor value and no hand-in in the game data. It lifts only the item-class protections; a quest that still asks for the item keeps it safe (0.7.6).
- **Artisan crates are in the known-use list.** A Waylaid Crate uses up crafted goods and becomes a Sealed Artisan Crate, handed in for the currency that buys profession recipes. They report `lootable=0` because they open by a spell, so the list is what explains their silence in the tooltip (0.7.6).
- **The addon sits under Inventory in the AddOns list** (`## Category: Inventory`, the game's own name for bag, bank and guild bank addons) (0.7.6).
- **A dot is checked against the button that carries it.** A bag addon that recycles a button for an empty slot never calls us, so a dot whose button shows no icon is hidden on every scan and again when the button is shown (0.7.6).

## Turned down

- **Lighter armor type as "not an upgrade"** (warrior with cloth or leather). Item level and quality are all we have, and a lighter piece with the right stats can beat a worn plate piece. The only sound check is armor value against the worn item, which needs equipped-item tooltips and still ignores stats.
- **Hints for Craftsman's Writs of a profession you lack.** The quest data has no skill requirement for them, so it would be a guess.
- **Hints for ammo with no matching ranged weapon.** The dump does not show equipped gear, and the ammo may be for an alt.
- **Hiding "Inventory is full".** That spam comes from fast-loot addons calling `LootSlot` into full bags. Filtering the game's errors would hide real ones too.
- **Waiting on a timer between deletes.** See "One delete per click".
- **Merging partial stacks to free a slot.** Checked on two real inventories; nothing would have been freed.

## Open

- **Sealed Artisan's Writ** (262890) has a spell that uses it up and says "a pending crafting order". It is silent for now. What it does is unconfirmed, so it is not in the known-use list.
